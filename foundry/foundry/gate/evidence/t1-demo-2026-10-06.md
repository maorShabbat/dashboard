## Wild
The sample game declares a wild but its reels contain none. The demo adds `W` to every reel set. In the 10,000 base books 10,755 of 19,302
revealed boards contain a wild, and about 5,800 of 10,546 win groups include a wild position (counted against the last reveal board, so
approximate after tumbles). The SDK's pay-anywhere evaluation counts a wild toward every symbol group; it never substitutes for scatter or
multiplier. Not yet covered: an independent oracle that re-evaluates boards (spec/MATH.md step 3).

## Findings
1. **Win-cap reel set.** A forced win cap (5,000x) never completed with a weighted multiplier share of about 1.4% (endless redraws, 69,000+
   attempts); 4.7% completed. The compiler now warns below 3%, and `verify.py` stops a run after `FOUNDRY_RUN_TIMEOUT` seconds with that advice.
2. **Sample quirks.** The official sample's mode quotas sum to 1.001; its base `freespin_triggers` values are ignored for the award (the game
   awards scatters x 2), only the keys act as thresholds; `check_game_repeat` in its `game_override.py` is never called. The compiler warns
   about the unused base values and enforces the event bound in `gamestate.py` instead.
3. **Cost of the check.** 10,000 books per mode took about 12 minutes on 4 cores (bonus buy dominates). Use 2,500-book batches (`run.batch`).
