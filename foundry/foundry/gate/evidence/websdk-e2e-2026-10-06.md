# Evidence: Web SDK `scatter` app playing Foundry books on the mock RGS

Date 2026-10-06. Test: `e2e/foundry/play.pw.test.ts` (`npm run foundry:e2e`, 4 tests, all pass; about 3 minutes in headless Chromium with
software WebGL). Frontend: the unmodified official Web SDK `scatter` app (`engineio/web-sdk` `1843d60c`, built with
`pnpm run build --filter=scatter`), which uses the sample art. It is a development stand-in; it is **not** shippable (Engine rejects sample assets).
Math: books produced by the Foundry compiler (`foundry_t1_demo`) and by real fixtures. RGS: `foundry/mock-rgs` reached by the game as
`https://rgs.test` (browser route to the local mock). Screenshots are written to `.cache/foundry/` (git-ignored).

| Test | What it proves |
| --- | --- |
| zero-win round | authenticate is the first call; space bar sends `POST /wallet/play` (amount 1000000, mode `BASE`); **no `end-round` after a zero win**; no page errors |
| winning round (book 3, 1.6x) | play, then end-round; mock balance 100.00 - 1.00 + 1.60 |
| bad `rgs_url` | no request reaches the RGS and no round is played (the visible error state is not asserted yet) |
| replay mode | `GET /bet/replay/{game}/1/base/3` is fetched, **no wallet call before or after the start click**, the round plays with a slimmed UI (no balance box) |

## Findings that change the Foundry design
1. **`rgs_url` is a host, and it must be HTTPS.** The Web SDK builds `https://${rgs_url}${path}`. So `rgs_url=rgs.test`, not a URL with a scheme; a
   local mock needs TLS or a browser-level route (the e2e uses a route). Spec `RGS_LIFECYCLE.md` updated.
2. **Mode names.** The app sends `mode: "BASE"`; the Math SDK publishes `base`. The mock matches case-insensitively. **Assumption to confirm on Engine
   staging** (the docs show `BASE` in `/wallet/play` and `SUPER` in the replay URL).
3. **End-round timing.** For a plain single-round win the Web SDK calls `end-round` immediately after `play`, holds the returned balance and shows it
   when the animation ends; for free-game (bonus) rounds it calls `end-round` after the animation (`createPrimaryMachines.ts`: `singleRoundWin` vs
   `bonusWin`). Zero wins never call it. The Engine docs say "close the round after all animations"; the SDK's own behaviour differs for plain wins.
   The generated app must keep the SDK's behaviour (it is what Engine reviews against) and the mock must not assume otherwise.
4. **Things that must be replaced before submission** (the stock build contains them): the "Mining Mayhem" art and symbols, `stake-engine-loader.gif`
   and `loader.gif` plus the "Add Your Loader" placeholder (checklist: no Stake Engine loader), the "TRANSLATIONS TEST" overlay, "ADD YOUR LOGO",
   "SCATTER GAME" title. Also console warnings "Uncompiled message detected" for untranslated labels (AUTO SPIN, BET).
5. **Replay.** The app supports `replay=true&game&version&mode&event&rgs_url`, skips authenticate and end-round, hides the balance, and starts after the
   start-screen click (there is no separate Play button). The Bet box shows $0.00 when no `amount` parameter is given: the checklist asks for the bet cost
   and applied multiplier to be shown, so the generated app must default the amount and show `costMultiplier` and `payoutMultiplier`.
6. **Ordering in the suite.** Pressing space before the game finishes loading is ignored; the e2e retries until the play request appears.

## Not covered yet
Bonus-buy confirmation, autoplay confirmation, resume of an active round (mock supports it), insufficient-balance behaviour in the UI, Popout/mobile
viewports, social mode and SC/GC display, sub-cent win display, a visible error for a bad `rgs_url`, junk `lang` values, sound toggle.

## Update: generated app (same day)
`foundry/compiler/frontend.ts` builds a Web SDK app from a compiled game (`npm run foundry:frontend`): the game's Math SDK frontend config
(`config_fe_<id>.json`, same shape as the sample's `config.ts`), keyed strings, a plain `FoundryLoader` instead of the Stake Engine loader and the
"Add Your Loader" placeholder, and the sample title, logo text and translations-test overlay replaced. `static/assets` is **linked to the sample art as a
development stand-in** (`devArt: true`, noted in `FOUNDRY_APP.md`): not shippable. Built with `pnpm install --prefer-offline` and
`pnpm run build --filter=foundry-t1-demo` (19 s). Run with `FOUNDRY_GENERATED=1 FOUNDRY_WEBSDK_BUILD=<web-sdk>/apps/foundry_t1_demo/build npm run foundry:e2e`:
all 5 tests pass (the 4 above plus a scan that the build has no stock loader file, no "Add Your Loader", "TRANSLATIONS TEST", "ADD YOUR LOGO" or
"SCATTER GAME", and shows the game name). Screenshot: the board shows the game title and "Foundry" in the logo slot.

## Update: generated rules screen (same day)
The generated app has its own modals composition (`FoundryModals.svelte`) and rules/pay table screen (`FoundryRulesModal.svelte`), built from the keyed strings
(including every heading); the SDK's placeholder "ADD YOUR GAME RULES / ADD YOUR PAY TABLE" screens are no longer in the build (scan test). The SDK's own
autoplay confirmation, bonus-buy confirmation, settings and sound modals are kept. e2e (now 7 tests, all passing with `FOUNDRY_GENERATED=1`):
- MENU > INFO shows modes with cost and description, RTP and maximum win per mode, per-symbol pays for every tier, wild/tumble/scatter/free spin/retrigger text,
  the UI guide and the Engine disclaimer; opening the rules never sends a play request.
- `social=true`: the same screen contains no restricted term (it caught a real bug: hard-coded headings such as "Pays" bypassed the wording pass; headings are
  now keyed strings: `rules.heading.*`).
Not covered yet: that the SDK's autoplay and bonus-buy confirmations actually appear (they are SDK components, not exercised), insufficient balance in the UI,
popout and mobile layouts, SC/GC display, sub-cent wins, junk `lang`, visible error for a bad `rgs_url`, sound toggle.

## Final status (same day): 13 of 13 e2e tests pass on the generated app
`FOUNDRY_GENERATED=1 FOUNDRY_WEBSDK_BUILD=<web-sdk>/apps/foundry_t1_demo/build npm run foundry:e2e` (about 6 minutes). Verified on the generated build:
- **No external requests**: only the game host and the RGS are contacted (rules and bonus-buy screens opened). Two defects found and fixed on the way: the
  Web SDK preloads a hosted font through `webfontloader` (replaced by an alias to a no-network stub, with a local-font fallback for the font name) and
  `app.html` linked a font stylesheet (removed).
- **Zoom disabled** (viewport meta `user-scalable=no`, `maximum-scale=1`, `touch-action: manipulation`) and **the page cannot scroll** (`window.scrollY` stays 0).
- **Junk language** (`lang=zz-ZZ`): the game loads and plays. Defect found and fixed: localized sprite keys such as `pressToContinueText_zz-ZZ.png` do not
  exist; the generated app now maps any unsupported language to English art (`spriteLang()`).
- **Bonus buy**: the screen shows this game's mode only (the SDK's default "Samurai Spin / Super Bonus" cards and their remote test-bucket images came from a
  global default and are replaced from the game's modes), buying needs a confirmation step, and nothing is played before it; the play request carries mode `BONUS`.
- **Autoplay** needs a confirmation: choosing a number of rounds plays nothing until "Start autoplay" is pressed.
- **Insufficient balance** ($0.50 against a $1.00 bet): no play request is sent.
- **Phone-sized touch viewport** (390x780): loads, plays a round, no horizontal scroll.
- Earlier: zero-win round sends no end-round; win closes with end-round; bad `rgs_url` reaches nothing; replay makes no wallet call; rules screen (normal and social) correct.
Test-suite notes: popups are rendered twice in the DOM, so tests click with `dispatchEvent` on the button rather than by coordinates; a failed test used to leave a
rendering page behind and slow the rest (contexts are now always closed).

Still not covered: sub-cent win display, SC/GC display without `$`, popout S/L layouts, a visible error for a bad `rgs_url`, sound toggle, canvas text in social
mode (the SDK rewords BET and BUY BONUS itself), fast-play legibility, older-device testing (manual).
